# Workflow 7 — Web & API

**Date:** 2026-07-20
**Roadmap:** `docs/superpowers/specs/2026-07-18-conformance-completion-roadmap-design.md` (Workflow 7 of 9)
**Crates:** armature-graphql, armature-graphql-client, armature-grpc, armature-openapi, armature-websocket, armature-http-client
**Findings:** 7 Critical · 25 Warning · 13 Info (45 total; see `TODO.md`)

## Problem

These six crates share one pattern more than any prior workflow: **config knobs and advertised features that are stored, never read.** A caller sets a value the builder happily accepts, and it has no effect on anything — the crate is telling them it did something it did not.

- **armature-http-client silently drops what it claims to protect.** `execute_with_retry` always clones the request via `clone_request`, which copies method/URL/headers but never the **body** — so any retried request (the crate's own documented POST-with-json-and-retry example) sends an **empty body** on every retry, and the per-request timeout is dropped in the same call. The circuit breaker fares no better: `reqwest` returns 5xx/429 as `Ok(Response)`, so the success arm always fires `record_success()` — the breaker can **never open on status-based failures**, which is the entire point of a circuit breaker guarding against a degraded upstream. `RateLimitInterceptor` logs a warning claiming it "respects rate limiting" and does nothing else — no delay, no retry, no signal to the caller. `Response::from_reqwest` converts a genuine mid-body network error into a silent empty-body `Ok`.
- **armature-grpc's "middleware" system implements nothing.** `Timeout`/`RateLimit`/`ConcurrencyLimit`/`LoadShedding`/`Retry` middleware structs hold a value and a getter — none of them implement `GrpcMiddleware`, a Tower `Layer`, or any actual behavior, and the `GrpcMiddleware` trait itself has zero implementors, so the `MiddlewareLayer<M>` scaffolding built to host them can never be constructed. `AuthInterceptor::intercept` is documented for server-side use ("validate") but unconditionally does the client-side `add_auth` and never calls `validate` — used as a server interceptor, it authenticates nothing and rejects nothing. Health-check registration binds and immediately drops the `HealthReporter`, so registered services never report `SERVING`. TLS, reflection, message-size limits, and TCP keepalive are all documented, config-exposed, and read by nothing.
- **armature-graphql-client's headline features — retry, caching, batching, type generation, federation — do not exist.** `retry_enabled`/`max_retries`, `caching`/`cache_ttl`, and `batching`/`max_batch_size`/`batch_delay` are all real config fields with real builder methods and are read **nowhere outside `config.rs`**. The crate's own lib.rs and README additionally advertise "Type Generation" and "Apollo Federation" as features; grep finds zero code implementing either — only the doc lines. `SubscriptionBuilder::header` is a Critical: it is documented to attach auth headers to a WebSocket subscription, and `execute_subscription` receives them as `_extra_headers` and calls `connect_async` with the bare URL — headers are silently and completely dropped, which for an authenticated subscription is a silent auth bypass on the client's own intent.
- **armature-graphql's security-relevant config is decorative.** `GraphQLConfig::production()`'s own doc says introspection is "Disabled for security" — but nothing in the crate ever calls `.disable_introspection()`/`.limit_depth()`/`.limit_complexity()`; every schema is built with a bare `Schema::build(...).finish()`, so a caller who configures `production()` still ships a fully introspectable, depth-unlimited schema believing otherwise. `FederationGateway` documents a runnable server (`gateway.listen(4000).await?`) that has no `listen()` method at all. `compose_supergraph` is named and typed as schema composition but only concatenates raw SDL strings with comment separators — the output is not a valid supergraph and cannot be fed to a real federation router.
- **armature-openapi's documented primary usage does not compile.** The README's Quick Start is built entirely around `#[derive(OpenApi)]`, `#[openapi(...)]`, `#[derive(ToSchema)]`, and free functions `swagger_ui()`/`openapi_spec()` — none of which exist anywhere in the crate, which has no proc-macro dependency at all. The only real API is a manual `OpenApiBuilder` plus `swagger_ui_response`. Copy-pasting the documented Quick Start does not compile.
- **armature-websocket's connection-management config is inert, and its liveness reporting lies.** `max_message_size`, `heartbeat_interval`, and `connection_timeout` are stored on both the server and client config and read by nothing — connections accept unbounded message sizes and are never proactively pinged despite "Heartbeat/ping-pong support" being an advertised feature. `WebSocketClient::is_closed()` reflects only a locally-set flag: a remote-initiated close or a dead reader/writer task leaves it reporting `false` (open) on a connection that is, in fact, dead, and `send()` on that connection keeps returning `Ok` into a channel nothing reads.

None of these are memory-safety bugs. All of them are a caller doing exactly what the documentation tells them to do — configure retries, configure a circuit breaker, configure introspection-off, configure a heartbeat, attach an auth header to a subscription — and getting silent, undetectable non-behavior instead.

## Goal

Make every advertised unit in these six crates conformant: either implement the behavior the docs/types/builders promise, or narrow the claim to match what the code actually does (`reconcile: claim`) where implementing it is out of scope. Close the two genuine correctness/security bugs first (retry sending an empty body; the circuit breaker that can never open on status failures; the silently-dropped subscription auth headers), then the "advertised, never wired" config knobs, then the stale README/doc examples.

Non-goals: a GraphQL code-generation implementation for `armature-graphql-client` (the finding's suggested reconciliation is to drop the claim, not build a codegen pipeline); real Apollo Federation subgraph composition (rename/redocument `compose_supergraph` rather than implementing composition); OpenAPI derive macros (implement the manual-builder-only reality in the docs, unless the plan phase finds the macro surface is small enough to be worth adding — decided in the plan, not here).

## Approach

One workflow → one PR to `develop`. The six crates are disjoint (no crate in this workflow depends on another), so implementation fans out one edit-only agent per crate, ordered by severity: **http-client → grpc → graphql-client → graphql → websocket → openapi**.

- **armature-http-client**: capture the request body (and per-request timeout) before the first send attempt so `execute_with_retry` can rebuild a fresh `reqwest::Request` per attempt instead of relying on `clone_request`'s lossy copy; gate `CircuitBreaker::record_failure`/`record_success` on response status (`status.is_server_error()` or the existing `should_retry_status`), not on `reqwest::Result::Ok`; make `RateLimitInterceptor` actually sleep for the parsed `Retry-After` duration (or surface it typed to the caller); make `Response::from_reqwest` fallible and propagate a body-read error instead of `unwrap_or_default`.
- **armature-grpc**: implement `GrpcMiddleware`/Tower `Layer` for the five middleware structs and wire `MiddlewareLayer` to actually apply them; split `AuthInterceptor` into a client-side (`add_auth`) and server-side (`validate`) path, or give the server-facing use of it a call to `validate`; retain the `HealthReporter` and call `set_serving`; apply `max_recv_message_size`/`max_send_message_size` via the generated service's decoding/encoding limit setters; apply `tcp_keepalive` on both server and client; wire the `retry_enabled`/`max_retry_attempts` client config into a real retry (a tower retry layer is idiomatic here, consistent with the middleware work above); enable TLS via tonic's `tls-ring` feature and config-driven `ClientTlsConfig`/`ServerTlsConfig`, or drop the README's TLS claim if this is deferred; register a real `tonic_reflection` service when `enable_reflection` is set.
- **armature-graphql-client**: implement the subscription header path — build a `tokio_tungstenite` `ClientRequestBuilder`/`http::Request` from the WS endpoint, apply each `(name, value)` from the builder's stored headers, and pass that to `connect_async` instead of the bare URL string (this is the Critical: closes a silent auth-header drop on subscriptions). Implement retry (honoring `retry_enabled`/`max_retries`, retrying on transport/5xx) and batching (honoring `batching`/`max_batch_size`/`batch_delay`) in `execute_request`/`batch`, or remove those config fields/builders and the corresponding README claims — decide per-feature in the plan, since retry is cheap and worth implementing while batching may be better dropped than half-built. Remove the Type Generation and Apollo Federation feature claims from `lib.rs`/README (no code exists for either); respond to a server `Ping` frame with `Pong` in `execute_subscription` instead of only logging.
- **armature-graphql**: add a `configure(SchemaBuilder) -> SchemaBuilder` (or equivalent) path that applies `max_depth`/`max_complexity`/`enable_introspection`/`enable_validation`/`enable_tracing` from `GraphQLConfig`, and wire it into every schema-building entry point so `GraphQLConfig::production()`'s introspection-disabled claim is actually true. Fix `create_merged_schema` (either implement real merging over a `MergedObject` root, or remove the function rather than shipping one that panics on `.build()`). Rename/redocument `compose_supergraph` and `ComposedSchema.sdl` to describe SDL concatenation, not composition, unless the plan finds real supergraph composition is in scope. Either implement `FederationGateway::listen` or rewrite the module doc to describe only the query-forwarding client that actually exists; make `resolve_entities`'s hardcoded `_entities` query select more than `__typename` (or document the stub).
- **armature-websocket**: build a `tungstenite` `WebSocketConfig` from `max_message_size` and pass it via `accept_async_with_config`/`connect_async_with_config` on both server and client; spawn a per-connection `tokio::time::interval(heartbeat_interval)` task on the server that sends `Message::ping` and tracks liveness (closing/marking dead on missed pongs); apply `connection_timeout` via `tokio::time::timeout` around the read loop; set the client's `closed` flag when the reader/writer tasks actually terminate (remote close or send error), not only on local `close()`/`Drop`.
- **armature-openapi**: rewrite the README Quick Start and Features list to the real manual-builder API (`OpenApiBuilder`, `swagger_ui_response`, `spec_json_response`), dropping the Auto Generation/Type Inference/Validation/derive-macro claims that have no implementation — unless the plan finds a small, well-scoped macro surface (e.g. a `#[derive(ToSchema)]` for simple structs) is worth adding within this workflow's budget, in which case implement it and keep the claim. Add the missing `OpenIdConnect` variant to `SecurityScheme` if OpenID is to remain an advertised auth scheme, or drop it from the doc list. Note (not necessarily fix) that `swagger_ui_response` pulls Swagger UI from a CDN, contradicting a "built-in" framing — reconcile the claim.

### Verification (via `armature-testkit`, `docker_available()`-gated where needed)

- **StubServer** — http-client: assert a retried request carries the *same* body and headers as the original (not empty), and that a 500/503 response opens the circuit breaker after the configured threshold. grpc/graphql/graphql-client: these are mostly in-process (tonic/async-graphql/graphql-ws over an in-memory or loopback transport), so a lightweight local server (tonic's own test helpers for grpc; a minimal axum/hyper handler for graphql-client's HTTP+WS paths) is more appropriate than the shared `StubServer`, which is HTTP/REST-shaped — decide per-crate in the plan.
- **Pure-unit / in-process integration** — grpc: an unauthenticated request against the server-side `AuthInterceptor` path is rejected; a registered service reports `SERVING` via the health-check client after startup; each middleware actually alters behavior (timeout middleware times out, rate-limit middleware rejects over the limit). graphql: `production()`'s built schema rejects an introspection query and a depth-exceeding query. graphql-client: a subscription connects with a custom header present in the recorded WS handshake request (assert via a local WS echo/inspection server); a server ping receives a pong reply. websocket: a client with `max_message_size` set rejects an oversized frame; a server heartbeat task actually emits pings on the configured interval (advance a paused clock in the test); `is_closed()` reflects a server-initiated close.
- Every implemented unit gets a regression test that **fails against the current code** — the pattern every prior workflow in this roadmap has followed, and the one this exact document's own sibling (`2026-07-20-workflow6-delivery-providers-design.md`) had to relearn twice: assert on the *specific* behavior a fix claims to add, not on something the pre-fix code already satisfied.

### Conventions

- rustls-only; heavy/native deps stay behind existing features; per-crate minimal `tokio` feature subsets per `AGENTS.md`.
- Where a documented feature is judged not worth implementing in this workflow's budget (Apollo Federation composition, GraphQL codegen, OpenAPI derive macros), the reconciliation is a **doc fix removing the claim**, not a stub — per the roadmap's `reconcile: claim` category, and consistent with WF6's rule that an unsupported operation gets an explicit error or an honest doc, never a fabricated success.
- Breaking changes (fallible constructors where a builder previously silently no-op'd, `Response::from_reqwest` becoming fallible, config fields removed alongside dropped feature claims) get a CHANGELOG Breaking entry and the crate's semver bump, per the project's 0.x convention (a MINOR bump signals breaking, per every prior workflow in this roadmap).
- Strict pre-commit/pre-push gate (`cargo fmt`, `clippy --workspace --all-targets --features full-with-saml -D warnings`) must pass, plus `cargo audit` and MSRV 1.89 clean, and CodeQL (a required branch-protection check since WF4) clean.

## Risks

- **Scope discipline on "implement vs. reconcile."** Several findings here (GraphQL codegen, Apollo Federation composition, OpenAPI derive macros) are genuinely substantial features disguised as small fixes. The default is reconcile-by-doc-correction, not silent scope creep into building a codegen pipeline; each such decision is made explicitly in the plan, not improvised during execution.
- **`armature-grpc`'s middleware trait design.** Retrofitting real `Layer`/`GrpcMiddleware` implementations onto five structs that currently do nothing risks a wider API shape change than a typical finding fix; the plan should settle the trait shape once, up front, rather than each middleware type inventing its own pattern.
- **WebSocket heartbeat/timeout testing without flaky sleeps.** Use `tokio::time::pause`/`advance` for interval and timeout assertions rather than real wall-clock sleeps, to keep the new tests fast and non-flaky in CI.
- **`armature-http-client`'s circuit-breaker fix changes observable behavior for existing callers** relying on the (broken) always-succeeds treatment of 5xx responses — flagged as Breaking in the CHANGELOG since a caller who never expected the breaker to open on status failures may see new `CircuitOpen` errors.
