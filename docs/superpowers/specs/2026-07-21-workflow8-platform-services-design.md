## Problem

The fourteen "platform services" crates are the cross-cutting infrastructure the framework leans on — caching, rate limiting, metrics, tracing, audit, config, feature flags, validation, i18n, real-time collaboration, and the admin dashboard. Across all fourteen the same failure recurs: **advertised behavior that the code stores but never performs**, and in several places behavior that is actively wrong on the request path.

- **Headline capabilities are hollow.** `armature-admin`'s `routes()` — the whole point of an "auto-generated admin dashboard" — registers no routes, renders no HTML, and returns view structs whose rows are hardcoded `Vec::new()` (`// Would be populated from database`); the dashboard has no database access at all. `armature-analytics`'s `AnalyticsMiddleware`, used as `.middleware(AnalyticsMiddleware::new(...))`, **implements no `Middleware` trait** — nothing is recorded automatically. `armature-features` advertises a `launchdarkly` feature and SDK dependency that no code references, and its `Operator::Matches` targeting arm is `{ /* Regex matching would go here */ false }`, so every rule using it silently never fires. `armature-toon`'s `to_string_pretty` calls `to_string` and adds no formatting. `armature-validation`'s entire documented API — `#[derive(Validate)]` with `#[validate(...)]` attributes — **does not exist** (only a hand-implemented trait does).

- **Observability reports fabricated data.** `armature-opentelemetry`'s `TelemetryMiddleware` records every HTTP metric with **literal hardcoded dimensions** — `http.method="method"`, `http.route="path"` — so all telemetry is uniform noise; it also never counts error-path requests and never installs a propagator (advertised W3C/B3 context propagation is a Noop). `armature-audit`'s `extract_user_id` returns the literal `"authenticated_user"` for any Bearer request, so audit logs never name the real principal. `armature-analytics` freezes all per-endpoint counters once `max_endpoints` is reached (the cap check wraps the whole update, not just insertion) and reports `requests_last_hour` as `requests_last_minute * 60`.

- **Request-path panics and fail-open.** `armature-ratelimit` panics with an integer divide-by-zero on any sub-second window, and its middleware **fails open** on a multi-hop `X-Forwarded-For` (the whole comma-separated header is `IpAddr::parse`d, fails, key becomes `None`, IP limiting silently disables for all proxied traffic); its `skip_on_error` and `key_prefix` knobs are dead. Three separate crates byte-slice UTF-8 on the request path and **panic on multibyte input**: `armature-metrics` (`&path[..97]`), `armature-audit` (`mask_value` — the core secret-masking primitive), and `armature-validation` (`MinLength`/`MaxLength` measure bytes while the error says "characters").

- **CRDT convergence is broken.** `armature-collab`'s `RgaText::operations` exports tombstoned characters as `Insert` of `'\0'` (a replaying peer resurrects deleted text as NUL) and never emits `Delete`; `merge` iterates peer nodes in nondeterministic `HashMap` order and ignores the causal `after` chain, so replicas can diverge; `OperationBuffer` on overflow keeps the oldest half and discards the newest (comment says the opposite); and the "Sync Engine" (`SyncProtocol`) is never wired into a session, so document state never transfers.

- **Inert config knobs and non-compiling READMEs, nearly everywhere.** `armature-cache` timeouts/pooling, `armature-collab`'s `SessionConfig` (6 of 7 knobs), `armature-admin` config, `armature-toon` flags, and `armature-opentelemetry` span-limits/interval are all read nowhere. And in the same class WF7 fixed for `armature-openapi`, **nine of the fourteen crates ship a README Quick Start that does not compile** (cache, compression, metrics, opentelemetry, audit, config, features, i18n, validation).

## Goal

Make every advertised unit in these fourteen crates conformant, prioritizing (1) request-path panics and fail-open security, (2) hollow headline capabilities, (3) divergent/fabricated data, then (4) inert knobs and non-compiling docs. Every implemented unit gets a regression test that **fails against the current code**. Verify with pure-unit tests plus `armature-testkit`'s `RedisContainer` (cache/ratelimit Redis stores) and `StubServer` where an HTTP surface exists — no live third-party services in the default run.

Non-goals: new backends or features beyond what is already advertised. LaunchDarkly and the `#[derive(Validate)]` macro are **built** (decided above). For the *other* genuinely-absent claims where building is out of scope — e.g. analytics Prometheus/Custom export backends, config Hot-Reload/Secrets/YAML/remote sources, audit JSON/database backends, i18n Fluent sourcing, compression async buffering — the finding is closed by **removing the feature/dep and the doc claim** (implement-or-retract rule), decided per-finding in the plan, never left as a hollow stub. Also out of scope: rearchitecting `armature-core`; a full OT/CRDT research effort beyond making `RgaText` converge for the documented single- and multi-character cases; a real admin ORM beyond wiring `routes()` to a mountable router over the model registry it already has.

## Approach

One workflow → one PR to `develop`. The fourteen crates are **disjoint** (no crate in this set depends on another in it except `armature-collab` → `armature-websocket`, already released), so implementation fans out **one edit-only agent per crate** (the WF3/WF6 pattern), dispatched in criticality-ordered waves; the coordinator runs the single central gate, `TODO.md`/`CHANGELOG` updates, and commit. Reuse over re-implementation:

- **regex** (already in the workspace via other crates) for `armature-features` `Operator::Matches` and `armature-validation`'s regex validator; **char-boundary-safe** truncation (`char_indices`/`chars().take`) for the three multibyte byte-slice panics.
- **prometheus** crate's real registry wiring for `armature-metrics` process metrics and a real `Summary`; the **opentelemetry** SDK's span-limit / periodic-reader / propagator builders for the tracing config knobs.
- **redis** connection-manager timeouts/pooling for `armature-cache`; the existing algorithm structs for `armature-ratelimit` `remaining`.
- For `armature-collab`, fix `RgaText` to emit real `Delete` ops and merge deterministically by the causal `after` chain (stable tie-break on node id), and wire `SyncProtocol` into `CollabSession`.
- For `armature-admin`, implement `routes()` as a real mountable router (using `armature-core`'s `Router`) whose handlers render the existing view structs to HTML, backed by a pluggable data-source trait rather than the hardcoded empty vecs.

### Verification
- **Pure-unit** — the bulk: divide-by-zero rejected/handled; multibyte inputs don't panic and count characters; `Operator::Matches` fires; `to_string_pretty` differs from `to_string`; analytics cap no longer freezes existing counters; opentelemetry dimensions reflect the real method/route; RgaText converges (delete replays as delete, two replicas of a multi-char interleave agree); inert knobs now change behavior.
- **`armature-testkit` `RedisContainer`** (`docker_available()`-gated) — cache Redis timeouts/pooling; ratelimit Redis `remaining` per algorithm; audit/ratelimit store round-trips.
- **`StubServer`** where a crate makes outbound HTTP (opentelemetry OTLP export shape, if reachable without a collector).
- Every non-compiling README is rewritten to the real API; where a crate has a `lib.rs` doctest that already compiles, mirror it.

### Conventions
- rustls-only; heavy/native deps (launchdarkly, otlp exporters) stay behind existing features; per-crate minimal `tokio`.
- Where a claimed capability is genuinely absent and building it is out of scope, **remove the feature flag + dependency + doc claim** rather than leave a hollow stub — never leave a `false`/`Ok`/canned-default masquerading as the feature.
- Breaking changes (fallible signatures, removed features, changed error classification such as `toon`'s `From` impl, `Ok(None)`-style contract corrections) get a CHANGELOG Breaking entry + a 0.x minor bump per the project's semver rule.
- Strict pre-commit gate (`cargo fmt`, `clippy --workspace --all-targets --features full-with-saml -D warnings`), full test suite with `ARMATURE_REQUIRE_DOCKER=1`, `cargo audit`, MSRV 1.89 — all green before the PR.
