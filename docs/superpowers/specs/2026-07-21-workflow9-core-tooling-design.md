# Workflow 9 — Core & Tooling

**Date:** 2026-07-21
**Roadmap:** `docs/superpowers/specs/2026-07-18-conformance-completion-roadmap-design.md` (Workflow 9 of 9)
**Crates:** armature-core, armature-proc-macro, armature-macros, armature-macros-utils, armature-testing, armature-app, armature-cli, armature-ferron, armature-rhai, **armature-log** (orphaned in the roadmap's table — no workflow owns it; adopted here as the tenth "core & tooling" crate so the roadmap's zero-open-Warning goal is reachable)
**Findings:** 16 Critical · 48 Warning · 23 Info (87 total; extracted from `TODO.md` on `develop` after WF7)

## Problem

These ten crates are the framework's meta-layer: the macros that generate user code, the test kit that verifies it, the CLI that scaffolds it, the runtime that boots it, and the proxy/log layers under it. The audit found the workspace's worst conformance here — `armature-macros-utils` is 2/15 conformant — and the failures compound because this layer is what users trust to tell them the truth about everything else.

- **The macro layer lies at compile time.** `armature-macros`' headline `routes!` macro builds a `Route` struct literal against a field that is private — **any use of `routes!` fails to compile** (`src/lib.rs:248`), and the crate's only test is an empty function, so nothing caught it. `armature-proc-macro` ships `catch_attr.rs`, `guard_attr.rs`, and `middleware_attr.rs` but never `mod`-declares them, so the `#[catch]`/`#[guard]`/`#[use_guard]`/`#[middleware]`/`#[use_middleware]` decorators that armature-core's own docs tell users to import **do not exist as exports** (`lib.rs:6`). Its `#[cache]` macro generates a key from the function *name* only, so `get_user(1)` and `get_user(2)` share one cache entry — wrong data returned (`cache_attr.rs:15`) — and ignores every documented attribute (`ttl`/`key`/`tag`). In `armature-macros-utils`, the documented multi-arg forms of `bail!`/`ensure!`/`validate!`/`validate_required!`/`redirect!`/`json!` don't even parse, the `Model`/`ApiModel`/`Resource` derives emit none of the promised traits (`#[api(skip)]` still serializes secret fields), and `test_request!` ignores its arguments and always builds `GET /`.

- **Test infrastructure gives false green.** `armature-macros-utils`' `assert_json!` and `assert_status!` expand to `{ let _check = expr; }` — **they assert nothing**, so a wrong status or body can never fail a test (`test_helpers.rs:20`, `:33`). `armature-testing`'s `TestApp::get`/`TestContainer::get` return unconditional `None` and `TestApp::new` hands the app a fresh empty container, so every provider registered through `TestAppBuilder::register` is silently invisible to DI (`test_app.rs:14`, `:24`; `test_container.rs:29`). `DockerContainer`'s documented auto-stop-on-drop panics inside any tokio test ("Cannot start a runtime from within a runtime", `docker.rs:254`); the load runner ignores its rate limit and drops remainder requests (`load.rs:248`, `:261`); stored before/after hooks are never invoked (`integration.rs:146`).

- **The CLI discards user choices and misreports.** The `armature new` wizard prompts for database/features/Docker/CI, prints "Creating project with:" — then calls `new::run(&name, template, false, false)`, discarding every selection (`main.rs:1361`); the `--database`/`--docker`/`--ci` flags are likewise never forwarded (`main.rs:1897`). The `--template` enum advertises graphql/grpc/lambda/cloudrun but those branches abort with "Unknown template" **after** files were already written, leaving a half-created project (`main.rs:1891`). `doctor` prints "✓ All essential tools are installed!" regardless of failed checks and exits 0 (`main.rs:1850`); `validate` exits 0 on failure (`main.rs:1666`); `routes` statistics hardcode zeros (`routes.rs:52`); `--fields`, `--guard-type`, `--job-type`, `--auth`, `--path`/`--format`/`--middleware`, openapi `--with-logging`/`--with-retry`, and `mock --watch` are all parsed and ignored.

- **Runtime & scripting break their documented API.** `armature-app` documents `ctx.call(...)` everywhere but registers the binding as `invoke` — every documented handler fails at runtime (`bindings.rs:110`); module-level guards are collected and never enforced (`builder.rs:46`); the host knob is discarded because `Application::listen` hardcodes `0.0.0.0` (`runner.rs:64`). `armature-rhai`'s dynamic routes never populate `path_params`, so `request.param("id")` — the Quick Start example — always returns UNIT (`router.rs:160`); `call_after` hands scripts an empty response instead of the real one (`handler.rs:170`); `script_handler` panics in every calling context (`handler.rs:209`); catch-all `/api/*` also matches `/apix` (`router.rs:215`).

- **Infra knobs are silently inert.** `armature-core`: `CacheInterceptor` caches nothing (`interceptor.rs:110`), HTTP/3 0-RTT/flow-control knobs are never applied (`http3.rs:255`), three batch knobs are read nowhere (`batch.rs:160`), `micro::Compress` compresses nothing (`micro.rs:835`). `armature-ferron`: `to_kdl()` silently drops ports, error_log, add_prefix, backend timeout/headers — and the single-backend path keeps only the URL (`config.rs:593`, `:435`, `:563`, `:665`); the advertised notify-based auto-reload never spawns a watcher (`manager.rs:31`); the health checker marks backends Unhealthy on the 2nd failure regardless of the configured threshold (`health.rs:326`); `is_running` sends SIGCONT while claiming signal 0 (`process.rs:436`); log forwarding reopens the file and blocks a worker per line (`process.rs:262`). `armature-log`: env-var configuration is silently ignored unless `init()` is called despite docs saying it's automatic (`lib.rs:310`), and "TTY detection" never checks a TTY (`lib.rs:298`).

## Goal

Make every advertised unit in these ten crates conformant, prioritizing (1) the compile-time and test-infrastructure lies (they mask other bugs), (2) discarded user input and misreported results, (3) runtime API divergence, then (4) inert knobs, efficiency, and docs. Every implemented unit gets a regression test that **fails against the current code**.

Decisions already made (with the user):
- **armature-log is in scope** (2W/3I; otherwise unowned by any workflow).
- **CLI:** implement the four missing project templates (graphql/grpc/lambda/cloudrun) and wire the wizard/flag selections into real generation (database deps, Dockerfile, CI workflow, `--fields`, guard/job variants). **Retract** the db-migrations claim: remove the README "Database Migrations" feature bullet and either drop `armature db` or make it a clear non-zero "not implemented" error (final form decided in plan) — a real migration engine is new feature surface, not conformance.

Non-goals: a migration engine (retracted above); rearchitecting `armature-core`; new macro surface beyond what docs already promise; building a data layer for `derive_resource`'s "CRUD operations" claim (parse the `table`/`primary_key` attributes for real, narrow the CRUD claim to what ships — per-finding in plan); WF8's possible `#[derive(Validate)]` addition to armature-proc-macro (owned by WF8; see Coordination).

## Approach

One workflow → one PR to `develop`, branch `feature/wf9-core-tooling` (worktree off `origin/develop`). Ten edit-only agents, one per crate — the crates are pairwise edit-disjoint; the one cross-crate need (armature-app's host binding requires an address-accepting `Application::listen` variant) is assigned to the **core** agent as an additive API; although core's full slate is Wave 4, the core agent lands that one additive method before Wave 3 dispatches so the app agent can consume it. Agents dispatch in criticality-ordered waves (WF3/WF6/WF8 pattern); the coordinator runs the single central gate, `TODO.md`/`CHANGELOG` updates, and commits. Reuse over re-implementation:

- `Route::new(HttpMethod, path, handler)` already exists (`routing.rs:59`) — `routes!` rewrites onto it instead of the broken struct literal.
- The three unexported proc-macro attr files already exist — declare, export, and *test* them rather than rewriting.
- `assert_cmd`+`predicates`+`tempfile` are already armature-cli dev-deps; `trybuild` already proves macro crates in armature-mcp — extend both precedents, don't introduce new harnesses.
- `std::io::IsTerminal` (std) for armature-log's TTY check; `std::sync::Once`-guarded init in the `log()` entry point for auto-init.
- ferron's `notify` dependency is already declared — wire the watcher it was added for; drop the unused `handlebars` (and `kdl`, unless emission is moved onto it — lean drop) dependencies.

### Verification

- **trybuild + expansion tests** for the three macro crates: compile-pass for `routes!`, the newly exported attr macros, and every documented macro form (`bail!(NotFound, "…{}", id)`, `ensure!(cond, Kind, "msg")`, `json!(201, {...})`, `test_request!(POST "/users", body)`, derives); `#[should_panic]` tests proving `assert_json!`/`assert_status!` now fail on mismatch; a behavioral test that `#[cache]` keys differ for different arguments.
- **assert_cmd integration tests** for the CLI in tempdirs: each template (including the four new ones) produces its advertised file tree; `--database/--docker/--ci` and wizard paths emit the corresponding Cargo deps/Dockerfile/workflow files; invalid template fails **before** any file is written; `doctor`/`validate` exit non-zero on failure; `routes --format json|yaml|markdown` differ; `generate dto --fields` injects fields. Generated projects are **not** cargo-built in the default suite (workspace-heavy); a `#[ignore]`d smoke test may cargo-check one generated project.
- **Pure-unit** everywhere else: ferron `to_kdl` asserts every previously-dropped option (ports, error_log, add_prefix, backend timeout/headers/weight on the single-backend path), health threshold honored at exactly N failures, `is_running` against a spawned child; app/rhai via rhai-engine scripts (`ctx.call` resolves, `request.param("id")` returns the captured value, `call_after` sees the real response, `/api/*` rejects `/apix`); testing crate self-tests (registered provider retrievable via `TestApp::get`, DI reaches handlers, load-runner request-count exact, Drop inside `#[tokio::test]` doesn't panic); log output-format and auto-init tests.
- Confirm each of the ten crates' tests actually execute in CI's workspace run (the audit's stubs survived because nothing ran them; cf. the known CI feature-gap for member crates).

### Conventions

- rustls-only; per-crate minimal `tokio` features; heavy deps stay behind existing features.
- Implement-or-retract per the roadmap rule, decided per-finding in the plan; never leave a stub masquerading as the feature. Retract-leaning candidates: `derive_resource` CRUD claim, `derive_model`'s Serialize/Deserialize claim (a derive macro cannot attach serde derives; emit field-wise `Debug`/`Clone` impls and reconcile the rest), core's three batch knobs, `micro::Compress`/`CompressionMiddleware` (implement gzip only if a workspace-present compressor fits core's lean default; else rename honestly), ferron's `handlebars`/`kdl` deps, CLI db subcommand, `script_handler`'s sync form (deprecate or re-implement without block_on-in-runtime).
- Breaking changes (CLI db removal, `new::run` signature, testing-crate signature corrections, macro form changes) get CHANGELOG Breaking entries + a 0.x minor bump per the project's semver rule.
- Strict pre-commit gate (`cargo fmt`, `clippy --workspace --all-targets --features full-with-saml -D warnings`), full test suite with `ARMATURE_REQUIRE_DOCKER=1`, `cargo audit`, MSRV 1.89 — all green before the PR.
