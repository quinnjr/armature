# armature-files

File processing pipeline for the Armature framework — images, PDFs, and
archives.

## Features

- **Image Manipulation** — resize, crop, rotate, flip, blur, grayscale,
  watermark, EXIF auto-orientation
- **Format Conversion** — JPEG, PNG, WebP, GIF, BMP, ICO, TIFF
- **PDF Generation** — headings, wrapped paragraphs, tables, page breaks, with
  real Helvetica advance widths for measurement and alignment
- **Archives** — ZIP creation and extraction, hardened against Zip Slip,
  decompression bombs, and entry-count blowups
- **Fluent Pipeline** — chain load, process, convert, and save in one
  expression

This crate deliberately does **not** depend on `armature-core`: it is a
standalone file-processing library with no request, routing, or runtime
surface.

## Installation

```toml
[dependencies]
armature-files = "0.2"

# Or pick exactly the formats you need:
# armature-files = { version = "0.2", default-features = false, features = ["pdf"] }
```

Feature flags:

| Feature | Default | What it turns on |
| --- | --- | --- |
| `images` | yes | `image` + `imageproc` decoding, processing and encoding |
| `embedded-font` | yes | Bundles DejaVu Sans (~760 KB) as the text-watermark fallback font |
| `pdf` | no | `PdfBuilder` (via `lopdf`) |
| `archives` | no | `ZipBuilder` / `ZipExtractor` |
| `full` | no | All of the above |

With `embedded-font` off you must supply a font yourself, via
`Pipeline::with_font` or per-operation on `ImageOp::TextWatermark`; a text
watermark with neither is a clean error, not a panic.

## Quick Start

```rust,no_run
# #[cfg(feature = "images")]
# async fn example() -> Result<(), Box<dyn std::error::Error>> {
use armature_files::image::{ImageOp, ResizeFilter};
use armature_files::{OutputFormat, Pipeline, Position};

let result = Pipeline::new()
    .load("input.jpg")
    .await?
    .image(ImageOp::Resize {
        width: 800,
        height: 600,
        filter: ResizeFilter::Lanczos3,
    })
    .image(ImageOp::TextWatermark {
        text: "© 2025".into(),
        position: Position::BottomRight,
        font_size: 24.0,
        color: [255, 255, 255, 180],
        // `None` falls back to `Pipeline::with_font`, then to the embedded
        // font (requires the `embedded-font` feature).
        font: None,
    })
    // WebP encoding is lossless; there is no quality parameter.
    .convert(OutputFormat::WebP)
    .save("output.webp")
    .await?;

println!(
    "wrote {} bytes in {} ms",
    result.data.len(),
    result.processing_time_ms
);
# Ok(())
# }
```

The same operations have shorthands — `.resize(800, 600)`,
`.watermark("© 2025", Position::BottomRight)`, `.to_jpeg(85)`, `.to_png()`,
`.to_webp()` — when the defaults suit you.

Input is decoded under `DecodeLimits`, which cap both dimensions and total
decoder allocation, so a crafted header cannot force a multi-gigabyte
allocation. Override them with `Pipeline::decode_limits`.

## PDF generation

```rust,no_run
# #[cfg(feature = "pdf")]
# fn example() -> Result<(), Box<dyn std::error::Error>> {
use armature_files::pdf::{FontSize, PdfBuilder};

let pdf = PdfBuilder::new()
    .title("Report")
    .add_heading("Hello, World!", FontSize::H1)
    .add_text("Generated by armature-files.")
    .add_page_break()
    .add_table(&[vec!["Item", "Qty"], vec!["Widget", "2"]])
    .build()?;

println!("{} byte PDF", pdf.data.len());
# Ok(())
# }
```

## Archives

```rust,no_run
# #[cfg(feature = "archives")]
# async fn example() -> Result<(), Box<dyn std::error::Error>> {
use armature_files::archive::{ZipBuilder, ZipExtractor};

let archive = ZipBuilder::new()
    .add_file("notes.txt", "hello")
    .add_file("data/nested.txt", "world")
    .build_async()
    .await?;

let extractor = ZipExtractor::new(archive.data)
    .max_entries(1_000)
    .max_uncompressed_size(16 * 1024 * 1024);

let written = extractor.extract_to("./out").await?;
assert_eq!(written.len(), 2);
# Ok(())
# }
```

Extraction is hardened for untrusted input:

- member names are resolved with the `zip` crate's `enclosed_name`, so
  absolute and `../` names are rejected rather than followed;
- the total uncompressed size, the entry count, and the size of the archive
  container itself are all capped. The entry count is read from the End Of
  Central Directory record *before* the central directory is parsed, because
  parsing it allocates a record per member;
- extraction is staged in a temporary directory inside the target and only
  promoted on success, and a failure during promotion is rolled back;
- extraction never clobbers: a destination name that already exists — as a
  file, a directory, or a symlink — is an error. Names are claimed with
  `O_EXCL`, so nothing is written through a pre-existing symlink.

```text
│  └─────────┘   └─────────┘   └─────────┘   └─────────┘     │
│       │              │              │              │         │
│       ▼              ▼              ▼              ▼         │

```
