### `armature-cron`

- [x] **CronExpression::matches** (divergent) _(reconcile: code)_ — Doc claims "Check if the expression would execute at the given time", but the body ignores `time` for the schedule lookup: it takes the single next `upcoming(Utc)` occurrence from now and only returns true if its timestamp equals `time`'s. Any past time, or a future time that isn't the very next occurrence, returns false, so the method almost never answers the question it claims to.
  - **Fix:** Compute matching directly, e.g. check whether the second preceding `time` yields `time` as the next fire: `self.schedule.after(&(time - Duration::seconds(1))).next() == Some(time)` (truncated to whole seconds), rather than comparing against the next upcoming time from `now()`. — `src/expression.rs:66`
- [x] **CronScheduler::add_job** (silent-failure) _(reconcile: code)_ — Signature returns `CronResult<()>` implying the job was added, but the insert is done in a detached `tokio::spawn`, so it returns Ok before the job is registered (tests sleep 100ms to compensate). A duplicate name is only logged via `warn!` and skipped; the dedicated `CronError::JobAlreadyExists` is never surfaced, so callers get Ok for a job that was never added.
  - **Fix:** Make `add_job` async (or acquire the lock synchronously with `blocking_write`) and perform the insert inline; return `Err(CronError::JobAlreadyExists(name))` when the key already exists instead of spawning a fire-and-forget task that swallows the outcome. — `src/scheduler.rs:92`
- [x] **CronScheduler::start** (efficiency) _(reconcile: code)_ — The per-job spawned task acquires the global `jobs` write lock and holds it across the entire `job.execute().await`. Every job execution therefore blocks all other jobs, `should_run` checks, and `list_jobs`/`add`/`enable` calls, serializing the whole scheduler and directly contradicting the advertised "Async job execution" and `max_concurrent_jobs` config.
  - **Fix:** Clone the `JobFn`/needed state out under a short-lived lock, drop the guard, run the future without holding the map lock, then re-acquire briefly to update status/next_run/last_run/execution_count. — `src/scheduler.rs:193`

### `armature-diesel`

- [x] **PgPool::transaction_with_isolation** (divergent) _(reconcile: code)_ — Claims to run the closure in a transaction at the requested isolation level, but it runs `SET TRANSACTION ISOLATION LEVEL ...` on the connection BEFORE `conn.transaction()` opens the transaction. ### Key Implementation Details

#### Async Handler Bridging

```rust
// armature-python/src/handler.rs
use pyo3::prelude::*;
use pyo3_asyncio::tokio::future_into_py;

#[pyclass]
pub struct PyRouter {
    inner: Router,
}

#[pymethods]
impl PyRouter {
    fn get(&mut self, path: &str, handler: PyObject) -> PyResult<()> {
        let handler = Arc::new(handler);
        self.inner.get(path, move |req| {
            let handler = handler.clone();
            async move {
                Python::with_gil(|py| {
                    let coro = handler.call1(py, (PyHttpRequest(req),))?;
                    pyo3_asyncio::tokio::into_future(coro.as_ref(py))
                })?.await
            }
        });
        Ok(())
    }
}
```

#### Zero-Copy NumPy Integration

```rust
// armature-python/src/numpy.rs
use numpy::{PyArray1, PyReadonlyArray1};
use pyo3::prelude::*;

#[pyfunction]
fn process_array<'py>(
    py: Python<'py>,
    data: PyReadonlyArray1<'py, f64>
) -> PyResult<&'py PyArray1<f64>> {
    // Zero-copy access to NumPy array
    let slice = data.as_slice()?;

    // Process in Rust (releases GIL)
    let result = py.allow_threads(|| {
        process_data(slice)
    });

    // Return as NumPy array (zero-copy if possible)
    Ok(PyArray1::from_vec(py, result))
}
```

#### GIL-Free Async I/O

```rust
// Release GIL during network I/O for maximum concurrency
async fn handle_request(py: Python<'_>, req: HttpRequest) -> PyResult<HttpResponse> {
    // Release GIL while waiting for I/O
    let response = py.allow_threads(|| async {
        // All network I/O happens here without GIL
        fetch_from_database(&req).await
    }).await?;

    Ok(response)
}
```
